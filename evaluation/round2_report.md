## 1. 검색 개선 내역 (5단계)

1차 평가(`round1_report.md`)에서 실패 4건 중 3건(2·3·4번)과 13번의 반 정보 누락이 **검색** 때문이었다.
필요한 "반 구성" 조각이나 같은 동의 학원이 상위 8개 조각에 들지 못했다. 두 가지를 차례로 적용했다.

| 개선 | 내용 | 노린 문제 |
|---|---|---|
| **① 학원 단위 확장** | 검색에 걸린 조각의 학원(검색 순위 순, 최대 5곳)은 그 학원의 5개 섹션(기본 정보·반 구성·설명회·특장점·확인 필요)을 모두 넘긴다 | 학원은 찾았는데 "반 구성" 조각만 빠지는 문제 |
| **② 동·과목 필터** | 조각에 동·과목 메타데이터를 붙이고, 질문에 동·과목이 있으면 그 학원 문서 안에서만 검색한다. 조건은 `tool_call`의 `search_academies` 인자를 재활용하고, 도구를 부르지 않은 질문은 질문 속 동 이름·과목 낱말에서 뽑는다 | 의미 검색이 "수내동" 같은 조건을 걸러 주지 못해 다른 동 학원이 섞이는 문제 |

- 코드: `src/retriever.py`의 `retrieve_academies()`, `src/agent.py`의 `extract_conditions()`와 그래프 순서(`tool_call` → `retrieve`)
- Chroma 컬렉션을 `academy_docs_v2`로 바꿔 메타데이터를 넣어 다시 만들었다 (문서 내용은 그대로).
- 답변 모델·채점 모델은 1차와 같다 (`.env`의 `AGENT_MODEL_ID`, `JUDGE_MODEL_ID`).

### 개선별로 달라진 점 (trace의 retrieve 단계)

**① 학원 단위 확장**
- 2번: 검색 조각은 1차와 같았지만, 숲속문장영어학원의 다른 조각이 걸렸으므로 `반 구성`까지 함께 넘어갔다 → 답변에 "중1 기초반 월·수·금 16:30~18:00"이 들어갔다 (1차에는 없음).
- 13번: 걸린 수학 학원 5곳을 모두 확장해 다온길 `반 구성`이 들어갔다 → 1차에서 "확인할 수 없음"이라 답한 다온길 중2 내신대비반 시간이 답변에 들어갔다.
- 4번: 새벽등대 `반 구성`이 들어가 중2·중3 저녁반(19:00~21:00, 19:30~21:30)을 답했다.
- 한계: 상위 8조각이 학원 2~3곳에 몰리면 그 학원만 확장된다 (3·4번).

**② 동·과목 필터** (①에 더해 적용)
- 3번: `search_academies({"dong": ["수내동"], "subject": "수학"})` 인자를 재활용해 수내동 수학 학원 문서만 검색했다. 검색 8조각이 1차의 "정자동·야탑동 섞임"에서 "별빛계단·한결노트만"으로 바뀌었고, 답변에 한결노트수학교습소와 "교습비 정보 없음"이 들어갔다.
- 1번: 정자동 수학으로 좁혀져 검색 조각이 8개(3곳)에서 5개(다온길 1곳)로 줄었다. 정답과 무관한 조각이 빠졌다.
- 2·4·13번: 동이 없고 과목만 있는 질문이다. 상위 조각이 원래 같은 과목 학원이라 필터 전후 검색 결과가 같았다.

### 남은 문제

- **4번 (시간 조건)**: 모든 반이 저녁 7시 이후인 물결소리영어학원과 푸른정원(중2 영어 20:10)은 여전히 검색되지 않았다. 상위 8조각이 새벽등대·달빛책장 2곳에 몰렸고, 의미 검색이 "저녁 7시 이후"와 "19:00"을 잘 잇지 못한다. 19:00에 끝나는 반을 표에 넣는 생성 문제도 남아 있다 (경고 문구는 붙임).
- 후보: 조각이 아니라 **학원 단위로 순위를 매겨** 서로 다른 학원을 더 많이 가져오기, 반 구성 조각에 "저녁반(19시 이후)" 같은 시간대 표시를 넣기.

## 2. 2차 평가 결과

### 평가 방법 (1차와 같은 조건)

| 항목 | 내용 |
|---|---|
| 평가 세트 | `evaluation/test_queries.csv` 15문항 (1차 이후 수정 안 함) |
| 답변 모델 | `global.anthropic.claude-sonnet-4-6` (`.env`의 `AGENT_MODEL_ID`) |

| 스크립트 | `evaluation.generate_answers` / `evaluation.score_answers --round round2` |

**RAGAS 실행 설정만 바꿈 (채점 방식은 그대로)**
학원 단위 확장으로 contexts가 길어져(아래 표), faithfulness 채점 호출 하나가 오래 걸려 시간 초과로 두 번 멈췄다. 그래서 `score_answers.py`의 실행 설정만 바꿨다.

| 설정 | 1차 | 2차 |
|---|---|---|
| 채점 모델 Bedrock 응답 대기 (botocore `read_timeout`) | 60초 (기본값) | 300초 (채점 모델에만. 에이전트 모델은 그대로) |
| RAGAS 문항 제한 시간 (`RunConfig.timeout`) | 180초 | 600초 |
| 동시 호출 수 (`max_workers`) | 2 | 2 |
| 한 문항 실패 시 | 전체 중단 | 그 칸만 NaN으로 두고 계속 (`raise_exceptions=False`) |
| LangSmith 추적 | 켜짐 | RAGAS 실행 중에는 끔 |

- 결과: **36칸(9문항 × 4지표) 모두 계산됨. NaN·에러·ThrottlingException 0건.**
- 답변 생성과 Judge 판정은 다시 하지 않았다 (저장된 결과 재사용).

### 지표 해석

- **context_recall +0.35 (검색 개선 ①②)**: 1차에 0.5 이하였던 1·2·3·5·10번이 0.75~1.00으로 올랐다. ①이 학원의 `반 구성`·`설명회`를 함께 넘기고, ②가 같은 동·과목 학원만 남겼기 때문이다. 4번만 0.00 그대로다 (아래 남은 실패).
- **context_precision +0.02 (거의 그대로)**: 2·10번은 크게 올랐지만, 5·6번은 내려갔다. 5번은 설명회 질문인데 ① 확장으로 학원 4곳의 다섯 섹션이 모두 들어가(1 → 18조각) 정답과 무관한 조각이 늘었다. 넓게 가져오면 recall은 오르고 precision은 떨어지는 트레이드오프다.
  - 3번은 첫 조각(별빛계단 `반 구성`)에 정답의 교습비가 그대로 있는데도 0.00이 나왔다. 조각별 판정 내용은 저장되지 않아 원인을 확인하지 못했다. 채점 모델의 판정 이상일 가능성이 있다.
- **faithfulness −0.02 (거의 그대로)**: 5번(0.83 → 0.68)이 가장 많이 내렸다. 나머지는 ±0.1 안이다. 근거가 길어져도 크게 지어내지는 않았다.
- **answer_relevancy −0.03**: 1번이 0.31 → 0.00이 됐다. 답변의 공공데이터 묶음에 "내신대비반인지는 확인할 수 없습니다"라는 문장이 있는데, 이 지표는 답변이 모호하다(noncommittal)고 판단하면 0점을 준다. 그래서 정책 1(모르면 모른다고 답하기)을 지킨 문장이 감점된 것으로 보인다. 5번은 0.52 → 0.94로 올랐다. 1차 리포트에 적었듯 이 지표는 긴 한국어 답변에 불리해 절대값보다 변화만 본다.

### 남은 실패: 4번 (평일 저녁 7시 이후 영어)

- **판정**: "시간 조건에 맞는 반만 제시" 미충족, "시간 조건에 안 맞는 반 추천" 위반.
- **원인 1 (검색)**: 도구를 부르지 않았고(동이 없는 질문), 과목 필터(영어)만 걸렸다. 상위 8조각이 새벽등대·달빛책장 2곳에 몰려, 모든 반이 저녁 7시 이후인 물결소리와 푸른정원(중2 영어 20:10)이 빠졌다. recall 0.00.
- **원인 2 (생성)**: 달빛책장의 17:00~19:00, 17:30~19:30 반을 경고 문구와 함께 표에 넣었다. 1차와 같은 문제다.
- 개선 후보: 학원 단위로 순위를 매겨 서로 다른 학원을 더 많이 가져오기, 반 구성 조각에 "저녁반(19시 이후)" 같은 시간대 표시 넣기, 프롬프트에 "조건에 맞지 않는 반은 표에 넣지 않는다" 규칙 추가.

## 다시 실행하는 법

```
.venv\Scripts\python -m evaluation.generate_answers --round round2
.venv\Scripts\python -m evaluation.score_answers --round round2
```
이미 저장된 답변과 판정은 건너뛴다. RAGAS만 다시 계산하려면 `round2_scores.json`에서 `ragas` 항목만 지우고 두 번째 명령을 실행한다.
